# ADR-001: pose_words как целевой pipeline для распознавания слов

## 1. Статус

Accepted

## 2. Контекст

В текущем репозитории одновременно присутствуют как минимум два отдельных режима распознавания слов: `words` и `pose_words`.

По зафиксированному текущему состоянию:
- `words` выглядит как более зрелый baseline/runtime путь для распознавания isolated words по RGB-видеоклипу;
- `pose_words` лучше соответствует целевой архитектуре проекта, поскольку уже включает pose extraction, нормализацию, feature composition и сегментационный слой;
- при этом `pose_words` все еще требует отдельной валидации на реальных, не dummy, артефактах и дополнительного подтверждения качества и эксплуатационной готовности.

Проекту необходимо зафиксировать единое направление развития, чтобы уменьшить путаницу в документации, кодовой базе и дальнейшей декомпозиции репозитория.

## 3. Решение

`pose_words` принимается как целевой основной pipeline для распознавания слов в будущей чистовой архитектуре проекта.

Режим `words` сохраняется как временный baseline/reference pipeline на переходном этапе. Он нужен для:
- сравнения качества;
- сравнения latency;
- fallback/страховки при миграции;
- технической валидации нового направления.

Ключевая формулировка решения:

**`pose_words` — основной путь развития проекта для распознавания слов, а `words` — временный baseline до подтверждения работоспособности и готовности `pose_words`.**

Окончательное удаление, заморозка или вывод `words` из основной линии допустимы только после прохождения validation gates для `pose_words`.

Формальный набор этих validation gates зафиксирован в [docs/validation-gates.md](../validation-gates.md).

## 4. Последствия

- Новая архитектура и новый чистовой репозиторий должны строиться вокруг `pose_words`.
- Документация должна отражать `pose_words` как целевой pipeline для распознавания слов.
- `words` не должен развиваться как равноправный долгосрочный product path.
- `words` пока сохраняется в черновом контуре как reference/baseline pipeline.
- Для снятия `words` с основной сцены нужны отдельные критерии готовности `pose_words`.
- Это решение уменьшает архитектурный хаос и фиксирует единый вектор развития проекта.

## 5. Что не означает это решение

Это решение:
- не означает немедленное удаление `words`;
- не означает, что `pose_words` уже полностью доказал превосходство по качеству;
- не отменяет необходимость дальнейшей валидации и тестирования;
- не запрещает использовать `words` как baseline в сравнительных экспериментах.
